## 15:51 — Pulse Check Link table (back-checks ↔ original pulse-check entries)
**Project:** PBIB project files\DQA 2026 (Rwanda DQA 2026.pbip, open in Power BI Desktop)
**Files touched:** live model only, via TOM on localhost:62427: new calculated table 'Pulse Check Link'; 4 new relationships; 2 relationships deactivated
**What was done:**
- Added 'Pulse Check Link', one row per client `unique_id` from back-checks (Survey where cd_stage = "pulse_check") ∪ Rwanda Pulse Check ∪ Kenya Pulse Check. It has 8,671 rows and the key is unique.
- Columns: unique_id (key), Country, Region, BDA (from the latest original entry), MEL Associate (from the latest back-check), Has Original Entry, Has Back-check, Link Status (Back-checked / Not back-checked / Back-check with no original entry), Original Submissions, Back-check Submissions, Latest Original Date, Latest Back-check Date, Days Original to Back-check.
- New 1→many single-direction relationships from Link[unique_id] to Survey, Rwanda Pulse Check, Kenya Pulse Check and Pulse Check Comparison.
- Deactivated (not deleted) the user-made many-to-many, two-way relationships Survey↔Rwanda Pulse Check and Survey↔Kenya Pulse Check, because they would make the filter paths ambiguous.
**Key decisions / rules:** "Latest" original = parsed SubmissionDate text, then KEY. Latest back-check = endtime, then KEY (same dedup rules as 'Pulse Check Comparison'). Rwanda and Kenya IDs never overlap.
**Verification:** 130 back-checked clients (Rwanda 79, Kenya 51), all of which have an original entry. 8,541 have not been back-checked. 33 clients have duplicate original submissions, and 2 clients were back-checked twice. All 209 measures returned the same values before and after the change. Filtering by Link Status/Country filters all four tables correctly. No report visuals used the deactivated relationships.
**Open items / next steps:** User must press Save (Ctrl+S) in Desktop to persist the change to the PBIP. Optionally add a Data Dictionary entry for the new table, or a slicer on Link Status on the integrity page.
